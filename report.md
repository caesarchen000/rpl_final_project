# ContactGen: Generative Contact Modeling for Grasp Generation
## Technical Report

---

## 1. Introduction

**ContactGen** is a deep learning framework for generating human hand grasp poses on 3D objects. It uses a variational autoencoder (VAE) architecture to learn object-centric contact representations, enabling high-fidelity and diverse grasp synthesis.

### Key Capabilities
- **Contact Map Generation**: Predicts contact probability at each point on the object surface
- **Partition Map Generation**: Assigns each contact point to one of 16 hand parts
- **Grasp Pose Optimization**: Generates realistic hand poses that align with predicted contacts
- **Multi-modal Output**: Supports diverse grasp generation through latent space sampling

---

## 2. System Architecture

### 2.1 Neural Network Architecture

ContactGen employs a dual-branch VAE architecture with the following components:

#### **Input Processing**
- **Object Point Cloud**: Raw 3D coordinates of object vertices
- **PointNet++ Encoder**: Extracts object features (`Feat` vector) from point cloud
- **Contact Map** (training): Ground truth contact probabilities
- **Part Map** (training): Ground truth hand part assignments

#### **Encoders**
- **Contact Encoder**: Processes object features + contact map → `Contact Latent` (z_contact)
- **Part Encoder**: Processes object features + part map → `Part Latent` (z_part)
- **Latent Regularization**: Both latents are regularized to N(0,1) via KL-divergence minimization

#### **Decoders**
- **Contact Decoder**: `Feat` + `Contact Latent` → Predicted contact map
- **Part Decoder**: `Feat` + `Part Latent` + `Contact Latent` → Predicted partition map (16-class logits)
- **UV Decoder**: `Feat` + `UV Latent` + partition features → Hand surface coordinates

#### **Output**
- **Contact Map**: Scalar values [0,1] representing contact probability
- **Partition Map**: 16-dimensional logits → softmax probabilities → hard assignments (0-15)
- **UV Map**: 3D coordinates on hand surface

### 2.2 Hand Part Structure

The system models 16 hand parts organized as follows:

| Part ID | Hand Part | Description |
|---------|-----------|-------------|
| 0 | Palm | Central palm region |
| 1-3 | Index Finger | Base → Middle → Tip |
| 4-6 | Middle Finger | Base → Middle → Tip |
| 7-9 | Ring Finger | Base → Middle → Tip |
| 10-12 | Pinky | Base → Middle → Tip |
| 13-15 | Thumb | Base → Middle → Tip |

## 5. Key Algorithms and Methods

### 5.1 Contact Map Generation

1. **Point Sampling**: Uniformly sample N points on object surface (default: 2048)
2. **Feature Extraction**: Use PointNet++ to extract object features
3. **Contact Prediction**: Decode contact latent → sigmoid → contact probabilities [0,1]

### 5.2 Partition Map Generation

1. **Logits Prediction**: Decode part latent → 16-dimensional logits
2. **Softmax**: Convert logits to probabilities: `probs = softmax(logits)`
3. **Hard Assignment**: `part_id = argmax(probs)` for each point

### 5.3 Combined Visualization

**Formula**: `vertex_color = PART_COLORS[part_id] × contact_probability × brightness_scale`

- **Partition Color**: Determines hue (which hand part)
- **Contact Probability**: Modulates brightness (how strong the contact)
- **Brightness Scale**: User-configurable scaling factor

### 5.4 Final.npy Generation

**Algorithm**:
```python
for each point i:
    part_id = argmax(part_logits[i])  # Find best hand part
    brightness = contact_map[i] * brightness_scale
    brightness = clip(brightness, 0, 1)
    
    if brightness < threshold:
        final[i] = zeros(16)  # All zeros if below threshold
    else:
        final[i] = zeros(16)
        final[i][part_id] = brightness  # Set only best part
```

**Purpose**: Provides explicit part-contact associations for downstream tasks.

### 5.5 Grasp Pose Optimization

1. **Initialization**: Random or pre-defined hand pose parameters
2. **Optimization**: Gradient-based optimization using:
   - **Contact Loss**: Align hand vertices with high-contact object points
   - **Penetration Loss**: Penalize hand-object intersections
   - **UV Loss**: Ensure proper hand surface alignment
   - **Regularization**: Smooth pose and shape parameters
3. **Output**: Optimized MANO hand parameters → hand mesh (`grasp_0.obj`)

## 7. Technical Details

### 7.1 Coordinate System Alignment

- **Object Meshes**: Automatically centered to origin before processing
- **Sample Points**: Generated in object-centered coordinate system
- **Hand Grasps**: Generated in same coordinate system for alignment

### 7.2 Point-to-Vertex Mapping

Visualization scripts use **nearest-neighbor mapping**:
- For each mesh vertex, find nearest sample point
- Assign color/brightness from that sample point
- Ensures smooth, coherent visualizations

### 7.3 Data Alignment

**Critical**: All `.npy` files must be generated together from the same `partial_demo.py` run to ensure:
- Same sample points (`sample_points.npy`)
- Same point ordering across all maps
- Correct alignment between contact, partition, and logits

### 7.4 Thresholding

**`final.npy` threshold**:
- Purpose: Filter out low-confidence contacts
- Effect: Points with brightness < threshold become all zeros
- Default: 0.0 (no filtering)
- Recommendation: Adjust based on dataset (typically 0.0-0.5)
